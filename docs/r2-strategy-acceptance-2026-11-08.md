# R2 策略整合独立验收与修复

2026-11-08，按用户要求以 UI、后端完整性、调度三路智能体和主线程集成验收。此前“已完成”的记录保留为过程历史；本轮以实际代码、受控测试与生产复核为依据。

## 发现并修复

| 范围 | 原问题 | 修复结果 |
| --- | --- | --- |
| 当前策略 UI | v9 已激活，配置与持仓仍显示旧算法 | 当前模式读取统一 workspace；旧快照标明不可执行，不回退旧推荐 |
| 表单协议 | 映射和复核提交返回对象，含服务端字段而被接口拒绝 | 仅发送写入协议字段，使用服务端版本和核验时间 |
| 复核体验 | 依赖英文协议字段和 JSON | 中文结构化事实编辑，保持未知字段；缺证保持待核 |
| 持仓操作 | lot 深链不能完成对应复核 | 逐批次身份、复核及受控退出提案入口，无身份明确先映射 |
| 资金完整性 | 部分取消后交易重核复活未执行金额 | 保留取消审计，只占用已发生和仍有效承诺 |
| 交易绑定 | 批次与切换腿匹配不完整，持仓快照误走旧逻辑 | 精确批次绑定，切换同时匹配两腿，兼容合法部分成交 |
| 到账 | engine 支持到账事实，但 API 没有可用写通路 | 受控到账核验与撤回版本，时间经过不冒充到账 |
| 手工决策 | 新记录仍默认旧策略，可携带伪造冻结证据 | 当前 v9 默认，人工事实明确未复核，不假冒合规推荐 |
| 冻结历史 | 备注编辑可能替换证据，完整快照超过手工输入上限 | 服务端保留原元数据，备注编辑不重传/覆盖机器证据 |
| 持仓评价 | 买入快照验证器拒绝持仓退出/切换计划 | 独立冻结计划流程评价；无原预测不制造收益结论 |
| 换仓约束 | 只比期限/回撤，缺整体组合重核 | 精确扣除当前 lot，重验单产品、策略族、档位、流动性及用款约束 |
| 补采接线 | 采集与合并函数存在但未被调用 | worker 补采公开身份，holding-only 证据进入监控，不扩充新增购买池 |
| 后台可靠性 | 同步计算阻塞 HTTP；投影失败后不再重试 | 独立 worker，有界超时、停止清理；结果不变也重试未成功投影 |
| 自动化 | 实际巡检仍依赖旧复核/旧入口 | 四项实际任务与仓库说明同步；频率、模型、状态、通知偏好保留 |

## 数据与运行契约

- 本轮不改 SQLite schema 或真实交易、收益、本金事实。现有 7 张策略表继续使用，数据库完整性和外键独立核验。
- 补采私有缓存为 `<ledger.sqlite>.holding-monitor.json`，绑定既有账本 UUID，只保存同份额公开证据和尝试状态；采用大小限制、哈希验证、排他锁及原子替换。失败不续期，跨日/换库不复用，降级结果保留既有有效批次，同输入最多 3 次，失败间隔至少 1 小时。异常终止遗留锁 10 分钟后可恢复。
- 策略 worker 硬超时 330 秒，公开补采最多 300 秒；停止时先请求取消并清理浏览器，再有界终止。
- 实际自动化 `r2`、`r2-2`、`r2-3`、`r2-4` 已通过应用工具更新；核对原模型、推理强度、日程、状态、环境、项目及通知偏好一致。样本外观察增加上游实际成功/数据日闸门。

## 保留的业务边界

- 证据不足、条款待核、流动性冲突或无可行满仓方案必须明确展示，不能制造合规建议。
- 实际到账、赎回权和费用仍需要对应事实证据；没有原收益预测的退出只评价流程，结果保持待核。
- 周末比较边界的合并披露归属仍按待核；真实切换前影子对照未执行，生产回滚未执行，原副本回滚证据保留。
