# 钱多多 R2 选品初筛改造计划

2026-11-07 · 阶段 0–3 本地验证，生产启用待授权 · 策略基线 [R2 初筛 v9](r2-product-screening-strategy.md)

## 1. 首版范围与现状

新增独立的「R2 选品初筛」工作台。每天可查一轮公开筛选结果，查看某个销售份额为何通过、观察、待核或淘汰，并沿证据进入交易前复核。首版独立验证，自动配置、换仓提案和既有持仓退出判断继续使用各自当前口径。初筛名额只表示公开证据下的研究顺序。

| 现有入口或链路 | 当前职责 | 本次改造位置 |
| --- | --- | --- |
| `/ledger/products`、`ProductsView.vue`、`ProductsSection.vue`、`ProductDialog.vue` | 配置目标、期限桶差额、持仓复核、产品快照 | 增加进入「选品初筛」的明确入口，保留原快照弹窗和「刷新配置快照」操作，两个刷新入口分别命名 |
| `fetch-cmb-r2-all.cjs`、`POST /api/products/refresh`、`lib/db.js` | 周 CSV 导入，整表替换账本内 `products`，供配置与样本观察使用 | 抽出无副作用的公共产品列表客户端，周任务沿原 CLI 与 API，日初筛直接使用客户端 |
| `server/lifecycle.js`、`automation-scheduler.js` | 账本维护、周期巡检、worker 与退出 | 在同一 Node 进程装配独立初筛调度和 worker。初筛网络请求使用独立并发、超时和恢复状态 |
| `R2LayoutView.vue`、`dashboard.ts` | 按路由加载账本 Dashboard 分区，缺账本时显示错误 | 新页共用应用外壳与侧栏，使用独立路由装配和初筛 store，绕过账本加载闸门 |
| `lib/yield-policy.js`、`lib/products.js`、持仓复核、决策提案与收益归因 | 期限调整参考年化、配置与账户判断 | 用现有接口回归验证隔离。初筛按公开最短持有期限分组，近 1 月年化仅在同类同期限中排序 |

试跑回归基线为 2026-11-07 的 984 个人民币公募 R2 份额。774 个低于门槛，48 个业绩待核，162 个收益达标。达标样本中 129 个售罄，2 个超期，1 个滚动持有待核，30 个通过数值门槛，其中 6 个频繁挂零。这个数量用于冻结样本复算，日更会随披露和额度变化。

## 2. 取数与规则引擎

新增 `server/modules/r2-screening/`，拆为公开来源 adapter、纯策略函数、repository、service 和 routes。生产任务、手动触发和 CLI 均调用同一用例。规则版本、日历版本、采集器版本随批次冻结。

| 顺序 | 取数和判断 | 失败及边界 |
| --- | --- | --- |
| 1. 产品池 | 招行统一查询平台 `queryProdList`，全量分页核对页数、总数和销售份额；筛人民币公募 R2/PR2 开放份额。证据键使用 `source + channel + sales_code`，登记编码用于交叉核验 | 同码跨渠道分开，错份额不能补用。全量页失败、范围不符或分页不一致时整轮不发布。销售渠道、起购及公开的客户限制保留为复核提示 |
| 2. 近 1 月业绩 | 同份额 `pastPerf` 的 A 项和 `zprfDat`，3M、6M、1Y仅保留对应披露。1M 低于 2.15% 淘汰，等于通过 | 距筛选日满 7 个自然日、无日期、份额不匹配或无值时待核。1M、净值各自判断有效期。查询时间不会延长披露有效期 |
| 3. 额度 | `mix/search` 匹配代码、名称、渠道，保留 `quota_status`、查询时间和可选的交叉字段。状态 0 通过，1 售罄，其余待核。移动货架按游标分页补公开金额 | 搜索同名匹配允许全半角归一化；金额保留原文，极小余额照录。状态 0 且无公开金额时显示「策略默认 >5,000 万元」，区分货架空白、未覆盖、请求失败。金额缺失不代替状态判断 |
| 4. 期限及分类 | 同渠道详情、说明书概览和必要的正式说明书确认封闭期、最短持有期、每日开放、定开与滚动。190 天通过，191 天淘汰，定开淘汰，滚动待核。用公开分类和合同条款区分纯债、存款类、固收增强，保留依据 | `term/datCyl` 可代表存续期，禁止据此覆盖最短持有期。期限不明可进入「期限待核」候选区，分类不明单列，不凑同类名额。届满后每个开放日可赎与未赎自动进入下个周期分别判断 |
| 5. 净值 | `getSAValueByPage` 校验成功码、份额、渠道、页数、条数、日期、披露精度。保存原始 `znavVal` 字符串与 `znavDat`，原始累计净值仅供对照 | 精确十进制或缩放整数比较，冲突同日值待核。单位净值计算不做分红复权。保留最新披露日、净值区间、条数和证据覆盖 |
| 6. 挂零、走势、回撤 | 交易日历过滤后最近 7 点比较 6 次，记录挂零次数和日期，≥3 次「频繁挂零」，不足或精度不明「挂零待核」。近三个完整自然月用四个应估值日端点，连续两次环比下降标「走势走弱」。按最新净值日回溯一年，历史更短用实际有效区间，计算峰、谷及首次修复 | 挂零和走势独立提示，不参与资格或排序。回撤 <1% 通过，1%–1.5%（含边界）观察，>1.5% 淘汰。回撤证据本身不足时单独待核。未修复、无回撤、证据不足分开显示 |
| 7. 结论及排名 | 保存所有已验证理由、主结论、提示标签。主状态为 `eligible / watch / pending / rejected`，另有 `shortlisted` 和组内名次。初版按公开精确天数 × 分类分组，1M 降序，同值按渠道与代码稳定排序，每组取最多 3 个，有 1–2 个时按实显示 | 未选入名额但通过门槛的仍可在「全部份额」查询。待核与观察分开，观察不占候选名额。权益上限 >5% 作为交易前复核标记，费率与比较基准不参与筛选 |

两套日历独立管理。刷新日历采用北京时间周一至周五，排除官方法定放假日期。净值计算用具备来源与版本的交易休市日历及明确的产品估值口径。月末按应估值日定位，缺端点时不给最近值补位。日历未覆盖本轮必须计算的日期时输出缺口，禁止猜测。适配器限并发、分页上限和整体超时，处理 429、超时和响应结构变化。签名从公开页面生成，短时内存复用并有限重捕，日志与持久层剔除签名、请求凭据和登录数据。浏览器使用独立无登录上下文。

交易前复核在详情页逐项展示公开证据与缺口。字段含正式最短持有期、确认日与预计最早资金可用日、赎回窗口/截止/确认/到账、App 实际额度、最新定期报告的资产穿透与久期、风险敞口。说明书授权范围与实际资产分别呈现。首版复核区只展示来源和待核项，账户事实和执行进入原工作台流程。

## 3. 数据库、迁移与恢复

新增本地独立 SQLite `data/r2_screening.sqlite`，支持 `R2_SCREENING_DB_PATH`。通过已核验的绝对路径拒绝指向账本文件。独立数据库采用外键、WAL、写事务和 schema 版本，避免初筛采集失败影响账本。首版不依赖旧 CSV 回填历史；首轮成功发布后建立历史。冻结试跑数据用于受控夹具。新库、WAL、SHM、备份和本地诊断缓存纳入忽略与发布隔离。

| 表 | 记录和约束 |
| --- | --- |
| `screening_runs` | 批次 ID、触发来源、北京时间业务日、预定时间、版本、状态、耗时、计数、错误摘要、输入摘要。定时逻辑批次按任务名与业务日唯一，手动批次带幂等键。保存 queued/running/succeeded/degraded/failed/interrupted 的事实 |
| `screening_attempts` | 批次下的执行次数、worker 租约与心跳、错误分类和重试结果。批次与尝试序号唯一；同一时刻至多一个活动采集，使用事务占有与发布令牌防止旧 worker 迟到提交 |
| `screening_evidence` | 批次、来源、份额、请求时间、披露日、分页计数、公开 URL、结构化证据摘要与哈希。说明书记录链接、文件哈希、登记码、页码或条款位置。可追溯原始净值和指标依据 |
| `screening_nav_series` / `screening_nav_points` | 按份额、数据内容哈希去重的不可变净值序列，点在序列内按净值日唯一。官方更正同一日期时生成新版序列，历史批次仍可复算 |
| `screening_results` | 每批次、每份额一行，含原始披露、类型和期限证据、额度事实/假设、结论与原因、组内排名、净值区间、挂零日期、三个月端点与收益、回撤和修复。可筛选字段使用结构化列，其余证据受控 JSON |
| `screening_current` | 单行当前可读批次指针，与结果发布同一事务。状态、类别、期限、近 1 月收益与代码建复合索引。当前批次和历史批次使用同一只读查询 |

网络阶段在事务外，完整性校验后短事务写入证据、结果和指针。权威产品池分页全量成功、结果数与合格输入数一致且主状态计数可对账后才允许发布。个别份额证据缺失可发布 `degraded`，相关份额按证据待核并显示覆盖率。核心来源全局不可用、主池不全或事务失败则保留上次可用批次，另记最新尝试与错误。跨日迟到或旧批次禁止覆盖更新批次。发布使用 SQLite 单写边界，GET 无持久化副作用。

独立增加 `r2:screen:db` 运维命令的 `preflight/init/status/backup/restore/verify` 子命令，复用现有 SQLite 在线备份能力，备份写到独立路径并校验完整性和外键。先在临时库演练初始化、版本升级、备份还原与失败回滚；首次启用前获新库 schema 授权。历史和证据首版不自动删除，记录容量与增长，达到运维阈值后再批准保留期。备份轮替用独立规则，禁止删当前或迁移前保护备份。关闭初筛开关、停止初筛调度、回退静态构建即可回滚入口；恢复初筛库只需停止其 worker 并用自己的备份，账本恢复流程独立。

## 4. API 与命令

在 `server/http/routes.js` 注册，在 `server/app.js` 装配依赖。接口统一前缀 `/api/r2-screening`，校验类型、合法日期、分页和排序白名单。沿用本机绑定、同源限制和 JSON 错误结构。所有外部 URL 由后端公开来源白名单生成。前端不会把公告内容当作 HTML 注入。

| 方法及路径 | 主要契约 |
| --- | --- |
| `GET /status` | `availability, timezone, scheduler, next_due_at, current_run, last_attempt, data_age, counts, source_health`，用于状态条与 Codex 摘要。未初始化或首轮未完成返回明确状态 |
| `GET /runs` 和 `GET /runs/:runId` | 分页历史、业务日、版本、状态、运行时段、来源覆盖、各阶段漏斗及互斥主结论计数。单批次保留诊断摘要，避免返回整批证据 |
| `GET /results` | `run_id` 缺省取当前。支持状态、正式候选、期限、分类、发行方、代码/名称、提示标签、分页与排序。默认每页 30、上限 100，返回固定批次 ID、总数、分组摘要和行数据 |
| `GET /results/:channel/:code` | 指定 `run_id` 查询行详情、规则解释、原始证据时间及来源、交易前核对清单。代码与渠道在首版固定来源范围内匹配 |
| `GET /results/:channel/:code/nav` | 同批次净值曲线或原始点分页，默认一段有限窗口，支持近期与一年查询，返回原始字符串以及挂零、峰谷、修复标记 |
| `POST /runs` | 手动刷新，`Idempotency-Key` 去重；首次接受为 202 并返回批次与状态地址，相同请求返回已有批次。其他运行占用时返回现有批次及冲突提示，前端加入查看；功能暂停或无可用库时明确报错 |

普通筛选、详情和导航均只读。固定批次的页面分页和深链始终带 `run_id`，刷新完成后由用户或页面显式切换批次，避免分页结果混代。手动刷新使用有上限的轮询或现有 HTTP 方式；仅当前页运行时轮询，页面切走终止请求。错误返回稳定机器码与可读说明，区分无批次、无匹配、源失败、参数无效和活动任务冲突。状态接口提供时效提示，原 `/api/health` 继续表示主服务健康。

历史结果按批次日保留当时判定。若当天刷新未成功，旧批次作为历史证据展示，表头标明日期与刷新失败，按当前北京时间额外显示业绩或净值过期提示和过期计数。即使旧批次仍在 7 天有效窗内，公开额度也保留上次查询时点。状态接口分别返回本轮历史候选数与当前证据时效，避免将旧候选误读为今天已核验。

新增 `npm run r2:screen -- --dry-run` 在临时目录采集与计算，`--fixture` 支持离线复算；受控运营 CLI 通过与页面相同的 service 触发或查状态。测试必须显式注入临时账本、初筛库、文件根、时间、日历和网络夹具。依赖、脚本路径、工作目录、浏览器可执行文件和生产隐藏启动方式都纳入启动自检。

## 5. 新页面与界面设计

新增理财侧栏「选品初筛」，路径 `/ledger/screening`，放在「产品与配置」之后。一个页面承载结果、批次历史和详情面板，历史/详情共享原路由查询参数 `?run=…&tab=…&channel=…&code=…`。首屏优先显示结果和证据时效；详情、运行记录按需请求。页面独立于账户数据加载。

```text
选品初筛                                      运行记录   [刷新初筛]
规则 v9 · 11/07 12:03 刷新 · 业绩/净值披露日期 · 批次状态
984 个份额   →   162 个收益达标   →   33 个额度状态为 0   →   30 个通过
正式候选   全部份额   回撤观察   待核   淘汰
[代码或名称] [期限] [分类] [发行方] [挂零/走势/额度提示] [重置]
期限与分类组   份额 | 1M / 3M | 回撤 / 修复 | 额度 | 挂零 / 走势 | 证据
                                                              分页
```

- **页头。** 「最近运行」和「当前展示批次」同时显示。简洁漏斗可点击过滤，明确「通过」与「正式候选」数量；来源部分失败、时效过期、停用或显示历史时在表格上方给出一条说明。初次运行骨架、成功但零候选、筛选无命中、网络失败与旧数据回退各有独立文案。
- **列表。** 默认正式候选，按期限与分类组织。代码与名称左对齐，1M/3M、回撤、额度对齐。表头说明数据日与净值口径，状态保留文字。低余额显示实际金额，额度假设显示「策略默认」，频繁挂零用琥珀提示加次数，淘汰才用危险样式。筛选可组合并保留 URL，状态计数与当前筛选语义明确区分，详情关闭回到原行焦点和滚动位置。
- **详情。** 宽桌面采用侧边面板，1280px 采用足宽面板；包含「判定」「净值与走势」「交易前复核」。展示判定理由和披露时间、原始 7 点表与日期、回撤峰谷及修复、四个月末端点及三段收益、来源链接和具体条款。图表默认有限窗口，切换近一年；关键点同时提供表格和文字。没有证据时显示待核原因。
- **运行记录。** 同页切换，列表展示定时、启动补跑、手动和重试；区分本轮结果、上一可用结果和最新尝试。查看历史不会改变当前发布指针。运行进行中可继续看上一轮，完成后明确提示结果可切换。
- **样式。** 沿用 `R2PageHeader`、主题变量、通用按钮与控件、Toast 和可用的对话框交互。新增作用域样式，延续钱多多的专业金融终端密度。信息文字至少 12px，收益、日期及金额 13px，正文 13–14px；正文对比度 ≥4.5:1，大字、图标和功能边界 ≥3:1。紧凑数字用等宽数字。浅色、深色及系统跟随按 1280×900、1440×900 验收，宽表仅容器内滚动。Tab、Enter、Esc、明显焦点、辅助技术可读状态和减少动态效果纳入验收。

## 6. 工作台调度、Codex 定时任务与消息

**唯一数据刷新负责人是工作台。** 初筛调度独立挂在 Node 生命周期，通过现有生产 Supervisor 随登录托管运行。北京时间周一至周五 12:00 触发，法定放假日和周末跳过。当天 12:00 后首次启动且当日无定时逻辑批次时补跑；已经完成或重试耗尽则跳过。崩溃中断可在当天接续原批次，跨日只记录中断并判断当天。定时、手动互斥；手动运行单独编号，不消耗当天定时名额。若定时触发时正有手动运行，排队等待并遵守当日截止。正常停机停止计时器、取消浏览器请求、等待或封存 worker 后关闭 SQLite。用可注入时钟测试，部署沿用当前 Windows 单登录触发、停止标记及独立托管。

| 本机 Codex 任务 | 首版安排 |
| --- | --- |
| `r2`，周一 08:30 | 保留周产品快照的命令、时间、输出和配置池更新。核对公共客户端抽取后导出结构及入库一致 |
| `r2-4`，周一 08:45 | 继续从周 universe 读冻结 cohort，独立样本节奏和阈值保持。验证初筛日更不会被算成样本 |

### 必测矩阵

- **规则。** 2.14/2.15%、数据年龄 6/7 天、190/191 天、定开/滚动/未知期限、同名异份额与跨渠道、额度 0/1/未知、0.01 元/空白、周末和休市净值、重复日期、原始精度与页面舍入、0/1/2/3/4 次挂零、7 点不足、月末端点缺失、回撤 <1%、恰好 1%/1.5%、>1.5% 以及同日并列和修复边界。
- **采集与事务。** 缺页、重复游标、接口签名失效、429、单份额证据缺失与核心源全挂；手动/定时同时请求、浏览器超时、重启恢复、午夜切换、旧 worker 迟到、事务中途失败、历史净值更正，以及源恢复后指针正常推进。
- **调度。** 周末、法定假日、节后首工作日、午前启动、12:00、午后补跑、同日重启、停机后跨日、运行中手动刷新、时区与夏令时环境差异。通过模拟时间验证，故障测试用临时目录、端口和一次性任务。
- **隔离与兼容。** 对比原 `/api/dashboard/products`、未开放快照、配置建议、持仓复核、提案和观察样本输出。在临时库核对 `product_daily_valuations`、`daily_records`、交易与本金事实以及原账本 schema/完整性。检查新接口不暴露本地路径、签名、截图或账户字段，GitHub Pages 构建白名单排除初筛。
- **验收命令。** 定向 Node 测试、`npm run check`、`npm test`、`npm run build`、`npm run test:e2e`、`npm run yield:verify`。涉及财务不变量时加覆盖率测试，依赖变化时加 `npm audit --omit=dev`，改动生命周期时加 `npm run test:daemon`，触及托管安装器才加 `npm run test:host`。发布后核对 `prod:status`、`run/host-state.json`、主健康与初筛状态 API、实际入口、stderr 和 stop marker。
