## 2. 固定 cohort

- cohort 在冻结时保存 689 个产品代码，后续采集不扩池、不替换代码。
- 新产品即使进入普通可买池，也不进入本观察 cohort；只在 `cohort_extra_codes_preview` 中记录，不参与排名变化。
- 已退出或暂不可买的产品保留在 cohort 定义中，并记录为缺失；不得用相似产品或新产品替代。
- cohort 原始存在率必须至少 90%，可评分覆盖率必须至少 80%，short/medium/long 每桶至少 10 个排名候选，且内部不变量全部通过，样本才可计入。
- `r2-term-yield-v1`、`r2-dynamic-v4` 或 B 方案发生变化时，本 cohort 观察停止；必须新建版本，不得跨策略版本继续比较。

## 3. 采集节奏与幂等

- 每个产品数据日最多一个样本。
- 相邻样本产品数据日间隔必须在 5–10 天；同一天多份文件、扩池文件或缓存刷新不能重复计数。
- 样本数据日取固定 cohort 中所有非空 `data_date` 的最大值；同时保存完整日期分布，不把混合披露日改写成统一日期，也不用单只产品的迟到日期回填历史。
- 周采集自动挂在既有 `r2` 周一产品快照任务使用的 `scripts/fetch-cmb-r2-all.cjs` 之后；同一数据日重复运行只返回 `duplicate`，不追加台账。
- `yield:observe` 使用独占锁和临时文件原子替换，只追加 `data/yield-observations/td-yield-002-weekly-ledger.jsonl`，不修改正式评分、目标、预算、提案或数据库。
- 首个规格后样本至少晚于基线数据日 5 天。
- 超过 10 天时不能把该快照计为样本，也不能继续静默等待；状态为 `cadence_broken`，由用户决定是否新建观察版本和基线。

## 4. 每个样本的指标

每个样本固定记录：

1. 五档证据计数、参考年化不可用数量与比例。
2. short/medium/long 的 B 方案前三、前十、前 5% 边界、参考年化中位数。
3. short 前 5% 正超额集中度；集中度、前 5% 和 31/101 边界评分诊断必须使用正式 B 方案，不能沿用 A/B/C 研究期的 A 方案诊断。
4. 各桶中仅依赖单一窗口（1M 或 3M）且进入前 5% 的产品代码。
5. 相对上一样本的 top1/top3/top10 重合度、Spearman 排名相关和排名换手率；Spearman 只使用两边都有有限名次的共同产品，并在计算前按共同产品重新排成 1..n，不能直接代入带缺口原始名次。
6. 31 天和 101 天边界两侧 4 天带宽的样本数、参考年化中位数和评分中位数；每侧至少 5 个候选才做经验判断。
7. `667828A` 的证据档位、可用窗口、B 方案评分/排名，以及是否仅凭单一 3M 窗口进入前 5%。
8. 上一快照优选产品在本快照的披露 1M 年化代理值，并明确标记它不是实际持有收益。

## 5. 预注册异常阈值

至少 4 个合格独立样本后才开始参数复核；8 个样本为优先目标。以下阈值不得在看到结果后修改：

| 指标 | 触发条件 | 严重度 |
| --- | --- | --- |
| short 前 5% 集中度 | 最近 4 个样本中至少 2 次 > 50% | 中 |
| 单一窗口高分 | 同一 1M/3M 单一窗口产品最近 4 个样本中至少 2 次进入桶内前 5% | 中 |
| short 前三稳定性 | 最近 3 次比较中至少 2 次 top3 重合 < 2/3，或 top1 变化 | 中 |
| short 排名换手 | 最近 3 次比较中至少 2 次 Spearman < 0.75 或 top10 重合 < 60% | 中 |
| 不可计算比例 | 最新样本 > 15%，或较窗口首样本上升 > 5pp | 高 |
| 31/101 边界 | 每侧样本足够且两侧评分中位数差 > 2 分 | 中 |
| `667828A` | 最近 4 个样本中至少 2 次仅凭单一 3M 窗口进入前 5% | 中 |
| 内部不变量 | 任一必要不变量失败 | 高 |

触发异常只表示“应发起参数复核”，不表示已经决定调参或回退。

## 6. 经济结果边界

- 排名相关、top3 重合度和披露收益代理只能证明横截面排序是否稳定。
- 下一快照的 `return_1m_annualized` 只是披露收益代理，不是用户实际持有收益，不用于直接评价策略赚钱能力。
- 参数变更还需要独立的经济结果证据，包括可核验持有期、费用、到账空档和实际到账收益。
- 在真实经济结果证据齐备前，观察结论只能写“排名稳定/不稳定”或“需复核”，不能写成“新口径更赚钱”或“旧口径更好”。

## 7. 参数复核入口

每周采集后自动运行 `yield:observe:review` 的同一纯函数逻辑：

- 少于 4 个合格样本：状态保持 `collecting`，不得调参；
- 4–7 个合格样本且无触发：状态为 `continue_current_policy`，继续静默收集并以 8 个为优先目标；
- 4–7 个合格样本且触发预注册异常：状态为 `review_required`，可以发起异常复核，但仍不得仅凭代理收益改权重；
- 达到 8 个合格样本：状态为 `review_required` 并产生稳定的 `preferred_sample_count_reached` 里程碑触发，完成样本外参数复核并由用户单独决定继续、调参或回退；
- 台账存在重复数据日、错误周间隔、未合格记录或篡改 cohort：状态为 `ledger_invalid`，停止计数并要求修复，不得自行补样本；
- 复核阶段必须重新校验台账保存的覆盖率、候选数、内部不变量、sample_index、策略版本和实际周间隔，不能只信任 `quality.eligible=true`；
- 任何触发都不自动修改正式权重、排名、目标或提案。

参数复核必须读取冻结 spec 和 cohort，先按 cohort 代码过滤每次快照，再按原始存在率、可评分覆盖率和分桶候选数重复质量闸门。报告必须记录 cohort 版本、代码数量、哈希和 spec 冻结信息；扩池产品不得进入样本外参数比较。

手工入口：

```powershell
npm run yield:observe
npm run yield:observe:review
npm run yield:observe:review -- --json
npm run yield:parameter-review -- --context stage6 --spec data/yield-observations/td-yield-002-observation-spec.json --cohort data/yield-observations/td-yield-002-cohort-v1.json --files <四个或更多合格样本文件，逗号分隔>
```
