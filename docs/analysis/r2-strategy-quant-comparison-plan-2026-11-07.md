# R2 两套选品策略量化对比方案

编制及满仓修正日期为 2026-11-07。按用户最新要求，100,000 元资金必须全部配置、现金目标为 0。已完成[满仓量化结果及验收说明](r2-strategy-quant-comparison-result-2026-11-07.md)，当前明细为 [full-investment-results.json](r2-quant-2026-11-07/full-investment-results.json)。原“只接受明确金额、允许留现金”的 E 组仅作为旧诊断留存，不再作为主配置结果。订单条款及底层穿透证据缺口继续单列。

用户最新额度口径：公开状态可买且额度金额空白的产品均按“大于 5,000 万元可买”处理，取消明确额度优先。是否披露金额不影响排序；有明确小额余额的产品仍按实际金额约束。同一策略 S/E 结果合并，E 仅保留兼容标签。

## 1. 比较目标

从全量公开产品及其可购买状态出发，分别运行之前的选品策略与初筛 v9，比较各自筛出的产品、排名、金额配置、额度依赖和历史风险特征。

核心问题有三项。

1. 两套策略为什么选出不同产品，差异来自哪些准入或排序规则？
2. 加入当时公开额度约束后，各自能配置多少资金，期限结构能否达到目标？
3. 较高的收益参考值伴随多少额度假设、近期冲高、短历史或集中度暴露？

本轮交付文档与临时计算结果。执行范围为只读取数、必要的公开数据补采与临时离线计算。

## 2. 产品范围与时间边界

### 2.1 全量起点

使用同一轮公开全量产品清单，覆盖人民币公募 R2/PR2 销售份额。按来源、销售渠道和销售代码匹配，登记编码用于交叉核验，名称只作辅助。

保留全量清单中的开放、售罄、未开放和状态待核记录作为覆盖审计。各策略独立判断准入资格，当前可购买性再由统一的额度与执行层约束。未开放和已确认售罄的产品新增配置金额为零。

不得将 v9 通过的 30 个、正式候选 17 个或旧研究池预先作为两套策略共同输入。已有 CSV 和初筛批次可作取数入口，均须先核对其过滤条件和遗漏记录。

对同一登记产品的不同份额分别计算收益、起购和额度，配置时检查底层策略集中度。跨来源重复记录合并，歧义记录列待核。

### 2.2 冻结信息集

执行时记录统一的信息截止时间 T，使用截至 T 已取得且在当时可见的数据。原始清单、请求时间、披露日期、策略版本、配置参数和结果均冻结留痕。

公开数据无法在同一秒取得，必须披露整轮采集起止时间，以及每笔额度的状态查询时间和金额查询时间。状态与金额冲突时列待核。

2026-11-07 已有批次可用于资料准备。若补采发生在之后，新增数据归入新的共同采集轮次，两套策略一起重算，不能将其标成 11 月 7 日的完整历史截面。

旧策略独有候选应补采与 v9 候选相同层次的额度、净值和条款证据。补采失败记录原因，不能将“未采集”记为策略淘汰。

## 3. 两套策略独立选品

| 项目 | 策略 O，原有策略 | 策略 V，初筛 v9 |
| --- | --- | --- |
| 规则基线 | r2-dynamic-v4、r2-term-yield-v1、front_load_scheme=B | docs/r2-product-screening-strategy.md 的 v9 |
| 产品准入 | 沿用原实现的风险、币种、公募、开放状态、合法期限、收益证据等规则 | 沿用 v9 的近 1M、期限、类型、净值、额度状态和有效期规则 |
| 收益依据 | 按期限桶计算参考年化及原有评分 | 近 1M 年化至少 2.15%，同类同期限按近 1M 排序 |
| 排序 | 原有 selection_score，包含 B 方案扣分及历史加分 | 按 v9 排序，挂零和走势走弱保留提示 |
| 期限分组 | 1–30、31–100、101 天以上 | 按 v9 的公开期限与产品分类分组 |
| 候选形成 | 沿用原有候选及配置顺序 | 前 3 名为研究优先名单；执行不足时按组内排序继续使用其余 eligible 合格替补，观察和待核不提升为可买 |

原策略的参考年化权重如下，缺失周期按原逻辑重归一化，缺失值保留空值。

| 期限桶 | 指定收益窗口及权重 |
| --- | --- |
| 短期 1–30 天 | 1M 20%、3M 50%、6M 30% |
| 中期 31–100 天 | 3M 50%、6M 30%、1Y 20% |
| 长期 101 天以上 | 3M 20%、6M 40%、1Y 40% |

执行前从代码冻结完整规则清单及版本，评分复用现有逻辑。原策略原生候选中额度未知或售罄的记录仍需保留，统一执行层另记其金额受阻原因。

v9 的 190 天上限、回撤门槛和近 1M 门槛只进入策略 V。原策略自身的准入门槛只进入策略 O。两套策略的规则差异必须在结果中可追溯。

v9 每组前 3 只保留为研究优先名单，不作为执行候选总数上限。资金未配足时继续遍历同组其他 eligible 产品，全部硬门槛不变；仅因研究名额未入前 3 名的产品可作为合格替补。同分依次按销售渠道、代码稳定排序。

## 4. 共同配置条件

第一轮比较新增资金配置，暂定资金为 100,000 元，独立于真实账户余额。这样可直接比较选品与额度的作用。

| 条件 | 主比较口径 |
| --- | --- |
| 满仓要求 | 配置金额必须等于 100,000 元，空闲资金为 0；未满仓时本轮配置验收失败 |
| 期限目标 | 短期 30%、中期 35%、长期 35% 为目标比例；保留单只与证据档位上限，满仓所需期限偏离须逐项披露；日开新增目标 0% |
| 短期流动性 | 单列 7–30 天或已核验 T+1 可赎部分，检查流动性要求 |
| 单只上限 | 30% |
| 收益证据上限 | 6M 档、仅 3M 档各自单只 10%、同档合计 20% |
| 仅 1M 产品 | 保留策略选品结果，自动配置金额为零 |
| 底层策略上限 | 50%，沿用已有产品系列映射，未知映射单列证据缺口 |
| 发行方 | 展示金额及比例 |
| 起购与订单 | 使用已核验起购额、追加规则、递增单位与单笔上限 |
| 配置顺序 | 优先按目标桶和策略顺序分配；补充 eligible 替补、补足已选产品；不因首轮单只目标切片而停止 |
| 桶间缺口 | 桶内候选及补仓仍不能消除缺口时，在不突破产品准入和风险上限的条件下跨桶配置，满仓且披露期限偏离 |

共同约束作用于配置层。某产品被策略 V 选中但因仅有 1M 历史未获自动金额，应同时保留“策略入选”和“配置受限”两个结论。

如原分配函数内部还包含选品过滤，离线调用前检查其是否重复施加策略 O 门槛。必须区分策略筛选和共同金额约束，避免隐含过滤改变策略 V。

单产品实际模拟金额同时受剩余资金、集中度空间、证据档位空间、可用额度、已知订单上限和起购递增要求约束。目标期限桶在第一阶段分配，跨桶补足单独记录。额度按同一产品最终累计金额占用，不在多轮补仓时重置。

期限、起购、递增或身份无法确定时，保留候选与待核原因，并继续寻找合格替补。金额低于适用起购要求时记为余额不足；明确余额不足不能套用大额额度假设。已选产品追加不重复施加首次建仓 5,000 元门槛，但仍满足适用银行门槛与递增。约束下确无满仓解时明确报告不可行，不伪造可购买状态或擅自放宽风险上限。

## 5. 额度情景与四组计算

| 计算组 | 策略 | 金额缺失处理 |
| --- | --- | --- |
| O-S | 原有策略 | 公开状态可买但金额缺失时，采用假设额度 |
| V-S | 初筛 v9 | 与 O-S 相同 |
| O-E | 原有策略 | 与 O-S 相同；保留标签，不设置明确额度优先 |
| V-E | 初筛 v9 | 与 V-S 相同；保留标签，不设置明确额度优先 |

### 5.1 公开状态情景 S

- 公开状态为 0，且有明确余额，按该余额约束。
- 公开状态为 0，但金额缺失，沿用 v9 的“大于 5,000 万元”策略假设。本轮 10 万元规模下视为额度不构成限制，相关金额全部标为假设配置。
- 公开状态为 1，新增金额为零。
- 状态缺失、冲突或无法精确匹配份额，新增金额暂为零并列待核。

### 5.2 取消明确额度优先，S/E 使用相同执行规则

所有合格产品按各自策略排序，不因金额空白扣分、延后，也不因披露金额获得优先级。公开状态为 0、金额空白时按用户规则“大于 5,000 万元可买”参与配置；披露金额时按该金额约束。继续使用合格替补、补足已选产品，必要时跨桶满仓。原始银行金额空白保留，用户规则来源另记，不伪造披露数字。

原“仅接受明确金额、其余资金不配”的计算保留在旧 results.json 与 previous-comparison.json.gz，作为披露覆盖诊断，不进入当前满仓主比较。

上一满仓版“明确额度优先”结果保存在 superseded-explicit-priority.json.gz，已撤回。当前 E 与 S 是同一规则的兼容标签，不再宣称存在两个独立额度情景。

额度原文统一解析为人民币元，保留原文、单位和解析结果。精确数值、上下界与策略假设分别存放。明确披露的“大于 X 元”只允许在已知下界支持范围内模拟，不能作为精确余额或无限额度。

公开余额属于查询时点的销售额度，实际账户限额、渠道资格和成交仍需验证。四组结果统一称为模拟配置。

## 6. 指标与计算口径

### 6.1 选品过程

输出全量记录数、身份匹配覆盖、各策略准入数量、待核数量、候选数量、正式入选数量和获分配金额的产品数量。

同一产品可能违反多个门槛，逐只保留全部原因。漏斗统计使用预先冻结的门槛顺序，每只只计入首个淘汰环节，以便数量对账。

输出共同选择、仅 O 选择、仅 V 选择三个集合，逐只写清门槛、评分或分组限额差异。

### 6.2 配置与额度

- 配置率为已配置金额除以 100,000 元。
- 各期限桶列目标金额、已配置金额和缺口。
- 明确额度支持率为明确金额支持的配置金额除以已配置金额。
- 假设额度依赖率为依赖默认额度的配置金额除以已配置金额。
- 已配置金额为零时，上述两个比例标为不可计算。
- 分配过程的阻碍区分售罄、余额不足、状态待核、起购递增受阻、集中度、证据档位和无合格候选，并记录通过替补、补仓、跨桶解决的路径。金额空白不等于余额为 0。

### 6.3 收益参考

所有组使用同一套期限加权参考年化评价，另列近 1M 年化，避免两套策略各用自己的优势指标宣布胜出。评分只用于排序，不能作为收益率。

已配置资金参考年化按配置金额加权。若部分产品缺少可计算的参考年化，则只对可计算部分展示均值，并注明其金额覆盖率，不能据此给全组合标注年化。

另列可计算部分的 90 天静态参考收益，使用“金额 × 参考年化 ÷ 100 × 90 ÷ 365”。该数值是统一换算，产品期限超过 90 天时仍标注锁定期，不解释成 90 天后可兑现收入。未配置金额与缺失收益数据部分保留未计算。

同时展示每组投入本金、可计算本金、未分配金额及收益数据缺口。不得仅凭已配置部分年化判断整组优劣。

### 6.4 风险与集中度

逐只列历史最大回撤、历史起止日、修复状态、有效净值数量、挂零、走势、收益证据档位与数据日期。组合列最大单只、前三只、底层策略占比，以及各风险提示涉及的配置金额占比。

历史区间不同须分别标注。产品最大回撤不能简单加权后当作组合最大回撤。净值分红和拆分未校正时，保留原始净值口径及其影响。

## 7. 比较与归因

在统一可买额度规则下比较原策略 O 与初筛 V。S/E 保留兼容标签，其配置必须一致；不再将标签间零差异解释为额度敏感性研究结果。

逐项归因于产品准入、排序、候选数量、额度、起购、期限桶或集中度。交互影响无法拆开时明确说明，不能把四组差值直接宣称为单一规则的因果效果。

结论使用可复核的具体描述，例如“满仓配置下参考年化相差 Y 个百分点”“7 天产品配置 X 元”“期限比例偏离 Z 个百分点”。单一时点结果用于评价当时配置差异，长期优劣留待后续收益验证。

## 8. 数据质量与验收

执行前形成覆盖表，至少包括全量主池分页完整性、两套策略独有候选的额度覆盖、收益窗口覆盖、净值覆盖、期限与起购覆盖。

必须满足以下检查。

1. 两套策略读取同一轮主池和冻结信息集，独立形成候选。
2. 每笔收益、额度和规则判断能定位来源、披露日期和采集时间。
3. 缺失、零值、假设和明确数值可区分，原始单位及百分比单位一致。
4. 四组配置金额均等于 100,000 元，未分配金额均为 0，按分对账；不满足时验收失败。
5. 各项共同约束逐项通过，余额不得被重复使用。
6. 结果逐只可复算，不能计算的项目附原因。
7. 某策略独有候选关键字段缺失时继续查证或寻找合格替补；仍无法满仓则报告约束不可行，不把部分配置当成完成交付。整体优劣判断仍受证据完整度限制。

## 9. 交付物

交付一份量化比较报告及其可复核明细。

| 内容 | 必备字段 |
| --- | --- |
| 四组汇总表 | 候选数、配置金额、期限缺口、参考年化及覆盖率、明确额度支持率、假设依赖率 |
| 全量选品明细 | 份额标识、O/V 准入与排名、全部判定原因、收益窗口、时间戳 |
| 配置差异表 | 四组逐产品金额、额度原文及数值、未配置原因、集中度检查 |
| 规则分歧表 | 仅 O、仅 V、共同选择，及各自选择和排除依据 |
| 数据质量附表 | 采集窗口、覆盖率、冲突、缺失、补采记录与局限 |

中间抓取数据和临时计算文件放入受控临时目录，报告所引用的必要证据与参数随结果留存，其余中间文件在结束时清理。

## 10. 后续观察与本方案假设

若本轮结果值得继续研究，可冻结候选与模拟配置，从冻结日之后观察收益、回撤、额度变化及成交差异。历史时点缺少额度快照时，不使用当前额度回填历史可买性。

本次满仓修正采用 10 万元新增资金、现金目标 0、30%/35%/35% 软期限目标和 90 天静态参考换算。S/E 执行顺序统一，额度金额空白按用户的大额可买规则处理，不设置明确额度优先。用户最新满仓要求优先，单只与证据档位风险上限保留；任何期限偏离单列。参数、共同采集窗口、原规则冻结和满仓执行规则见结果文档。

真实持仓换仓另设比较，需纳入确认日、可赎窗口、到账空档、费用与实际可成交金额。本次执行不涉及真实持仓换仓或账本写入。
