# TD-RESEARCH-TEMPLATE-001：统一调研报告模板

状态：已完成（2026-11-09，模板 v1 + 三入口卡片统一 + 首批 4 篇迁移）｜记录日期：2026-11-09

## 目标与现状

以 `report/金融科技-行业调研-2026-11-05.html` 的渐变标题区、浅色卡片章节、清晰表格和状态提示为视觉基准，建立统一正文模板及导航卡片契约。适配浅色、深色、桌面和静态报告移动阅读；保持各篇研究结论、数据和章节要求不变。

当前报告各自编写 HTML/CSS；`scripts/build-report-docs.mjs` 将正文和样式转换为应用阅读器数据，`src/components/report/ReportDocument.vue` 加载样式。白酒报告自带分栏和目录，应用阅读器另有目录，造成风格差异及目录重复。应用报告库 `src/views/InvestmentResearchView.vue`、独立归档 `research/index.html` 和 `scripts/report-nav.js` 中的悬浮导航分别实现报告入口，字段和样式需统一。`report/*.html` 仍是报告正文唯一可编辑源；生成物不手改。

## 设计与实现方案

1. **正文模板**：制定版本化的报告样式和 HTML 结构契约，提供可复用模板及示例。统一标题区、摘要、日期与方法元数据、章节卡片、结论/KPI 卡、提示与风险、表格、来源、免责声明和页脚。按个股、主题、快速扫描、事件更新保留必要章节差异，研究内容不因统一样式而删减。样式使用专用前缀或报告根节点作用域，避免影响工作台或通用导航；信息文字至少 12px，状态同时有文字或图形，满足对比度要求。
2. **主题与布局**：使用统一浅色/深色语义变量，静态报告遵循现有主题约定，应用阅读器服从应用主题；桌面为主，报告静态页同时覆盖移动阅读。表格仅在容器内横向滚动，根节点无横向溢出，长标题、长链接、空字段和大量内容可正常换行。
3. **目录与导航**：应用内只显示阅读器目录；静态报告保留通用导航和原生报告库首页入口，需要正文目录时与通用导航明确分工。对模板报告以明确标记识别内置目录，构建时仅移除应用内重复的导航，保留章节锚点和正文；不能用宽泛规则删除历史报告内容。
4. **导航卡片模板**：以应用报告库现有卡片为起点，统一标题、摘要、日期、分类、研究优先级及跳转层级，长内容、缺失值和当前报告有一致的呈现规则；统一语义色、边框、间距、悬停、键盘焦点和深色主题。应用库、独立归档及悬浮导航可按空间采用完整/紧凑两种布局，但字段语义与视觉规则一致；不改变筛选、搜索和链接行为。
5. **单一模板来源与静态兼容**：实现时选定一套可维护的模板/token 来源，由构建生成各入口所需样式与标记，避免三处各自复制后漂移。报告仍须包含非空正文和作用域化 `<style>`，可通过 `file://` 直接打开；若引入共享资源，必须纳入 Pages 白名单并验证离线及相对路径，不能要求服务端或网络。不得将 Vue 构建物、账本或市场简报带入公开产物。应用与静态入口读取同一报告元数据，保持现有清单、URL、锚点、检索和科技图谱关键词兼容。
6. **历史报告迁移**：先盘点报告中的内嵌样式、图表、图片、特殊表格、内链和目录，建立迁移清单；先迁移白酒报告作为试点，再按复杂度分批迁移。每篇只修改源 HTML 的结构和表现，逐项核对正文、数字、来源链接、元数据、锚点与图表；无法安全自动转换的报告人工处理。未迁移报告继续按现有渲染方式可读，不以通用覆盖破坏旧样式。

## 风险与回退

CSS 作用域转换、不同主题选择器和特殊图表可能改变旧报告呈现；模板必须先对样本和旧报告回归，按批推进。保留源文件与 Git 差异，出现问题时回退对应模板或该批源文件并重新构建发布；不得手改生成物。实施前检查工作区并保护已有未提交改动。本计划不授权修改研究事实、账本 schema 或账户数据。
