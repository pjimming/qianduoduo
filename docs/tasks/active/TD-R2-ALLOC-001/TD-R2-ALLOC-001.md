## 资金可用性

- 从可支配余额、已确认持仓批次和待确认交易推导资金可用日历。按最低持有期、实际赎回窗口、申请截止、交易日历、赎回确认和到账规则计算。区分已到账、可申请、预计到账和日期待核。待确认买入扣减可分配资金，待确认赎回按结算状态展示，避免把同一笔资金算两次。
- 逐个检查用款截止日。该日前可动用的累计本金，须覆盖累计计划用款和需同时预留的切换金额。切换预留可用「最迟到账时间＋最低可动用金额」表达，由实际机会窗口和资金需求确定。已用于前序支出或已被预留的资金只计一次。
- 把近期用款与切换预留分开显示，区分明确填报为零与尚未填报。存在规则缺口时列出估算和缺口，自动提案只使用有足够依据的金额与日期。锁定中的批次只生成开放后的观察结论。

## 收益比较与配置

对同一笔本金，在同一截止日比较长、短方案。用现有期限加权参考年化作为情景输入，按实际计息天数测算净收益，扣除申购、赎回等额外费用和资金空档。已计入净值的费用只计算一次。短产品能持续持有时按续持测算，必须滚动续作时单独披露续作假设和利率敏感性。

```text
净期限溢价（年化） = (长方案净收益 − 短方案基础净收益) ÷ 本金 × 365 ÷ 比较天数
切换机会价值（元） = 可成交概率 × max(0, 换成后同周期多赚的金额 − 额外交易费 − 空档损失)
加锁门槛（年化） = max(期限最低补偿, 切换机会价值 ÷ 本金 × 365 ÷ 比较天数)
```

- 净期限溢价达到门槛且所有用款约束通过，才建议延长锁定期。期限最低补偿以每多锁 90 天加 30bp 作为回放初始情景。参数正式启用前用历史快照和实际成交反馈校准。多锁天数以两条路径最早资金可用日之差计算。
- 切换价值只算比较期内可实现、且已有可用资金接不住的部分。可成交概率考虑额度、交易时间和到账路径，缺少数据时展示假设区间及对应门槛。机会窗口互相重叠时，按互斥情景计算，避免重复计价。
- 先剔除会造成任何资金缺口的方案，再跨桶比较净收益与切换机会成本。经济结果相近时优先到账更早、条款与额度更明确的产品。没有合格长端时可全部选短端或中端，候选不足时说明可暂留或等待的金额和原因。

## 验收

- 同净收益、同风险时优先更早可用的方案。长端净溢价足够且资金覆盖充足时允许配置。长桶零配置应是正常结果，即使长端收益较高，只要会错过用款截止日就淘汰。
- 覆盖同产品多批次、已过最低持有期但未到账、周末节假日和交易截止、赎回规则未知、额度售罄、费用和空档吞掉利差、集中度上限，以及待确认资金不重复计入。
- 决策可复算。能查看比较截止日、资金可用日、收益快照日、费用、空档、概率假设和拒绝原因。回放核对本金、历史交易及提案审计。实现阶段使用临时 SQLite 运行定向回归、`npm run check`、`npm test`、`npm run build` 与 `npm run test:e2e`，并检查桌面和移动端的流动性与收益展示。
