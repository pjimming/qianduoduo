# R2 v9 流动性优先改造计划

## 拟定规则

| 期限桶 | 产品期限 | 当前 v9 预算目标 | 拟定规则 |
| --- | --- | ---: | --- |
| 短期 | 1–30 天 | 30% | 合规资金优先承接；充分配置时至少 70% |
| 中期 | 31–100 天 | 35% | 硬上限 20%，可低配至 0% |
| 长期 | 101 天起，当前候选最长 190 天 | 35% | 硬上限 10%，可低配至 0% |
| 现金类 | 0 天 | 0% | 目标 0%，现金类产品仅展示；容量不足可出现待配置余额 |

两条上限独立生效，合计自然不超过 30%，各桶剩余额度不能互借。70% 是充分配置且现金类目标为 0% 时的结构结果。遇到短期合规容量不足，展示未配置金额与原因。沿用 v9 策略本金作分母，按分向下取整计算限额，投后占用取自统一账户敞口，涵盖持仓、待确认买入和有效预留，同一买入承诺去重。到账待核资金不可用于下单。

按产品约定期限分类，持有中的长期产品临近到期时仍占长期桶。另按每笔持仓核验最早可赎日和预计到账日，展示未来 7/30/90 天累计到账覆盖与未知项。沿用现有 30% 合格流动性底线和累计现金需求约束，7/30/90 天暂作观察视图。现金需求以实际付款日核对，资金最迟到账日应早于或等于付款日；买入开放日、待核赎回规则和到账在途均不能计入已可动用资金。

## 合理性与当前影响

20% / 10% 适合作为流动性优先的首版上限。两条线把中长桶上限锁在合计 30%，长期只占其中最多 10%，给短期留出足够的配置空间。上限是否足够，要用最早付款日的金额和到账覆盖验证。假设应急金在 R2 账户外，3% 年化作为进取目标；若近 7 天或 30 天有刚性付款，以上线前的现金流压力测试为准。

2026-11-09 按当前 v9 账户口径只读复算，实际持仓与承诺口径一致，短期 46.33%、中期 26.83%、长期 26.83%。中期超限约 6.83 个百分点，长期超限约 16.83 个百分点。按现行规则标记符合流动性条件的持仓占 29.67%，距现有 30% 底线约 0.33 个百分点。当前工作区还报出证据档单品上限和流动性或现金流冲突，单调期限参数不足以使现有组合满足执行条件。

短期容量是主要取舍。11 月 7 日历史冻结样本曾出现合规短期候选只能承接 20% 的情形，说明需要用当前产品池重新验算。收益用同一冻结输入和现行期限调整参考收益比较，分别列出可配置比例、已配置部分参考年化和按全账户本金计算的参考年化。作量级示例，若 23.67% 本金由中长转短，相关产品的年化收益差为 0.50 个百分点，组合参考年化约下降 0.12 个百分点。实际影响由候选、费用、到账空档及剩余未配置余额决定。

## 实施与过渡

1. 在 `contract.js` 单列中长期硬上限并升级配置策略版本。让 `allocation.js` 和 `replacement-constraints.js` 共享同一分币计算与校验。先保证到期现金需求与流动性，再在合规范围内尽量配置资金，短期优先，中长桶额度按需使用。保留产品、系列和证据档限制，求解诊断也不得放松中长上限。
2. 在提案生成、采纳及预留事务内复核最新账户占用和策略版本。旧版未采纳提案失效后重算；已采纳但未下单的余额复核后暂停执行或走既有取消释放流程。部分成交仅处理未执行余额，已发生的交易和到账照实记账。分步换仓逐腿校验，未核实到账的资金不得预支，重复请求不得重复占额。
3. 存量超限进入过渡状态。冻结超限桶的新增与续作，按核实的赎回窗口或到期顺序回落。允许赎回及降低超限、同时不恶化其他桶和现金流的合规操作，账户缺口明确显示。首批到账资金优先补齐已核实的近端现金缺口，再评估短期候选。工作区并列展示实际和承诺占用、剩余或超限额度、最早到账日、待配置余额和阻断原因。
4. 上线前用同一份生产一致性副本和公开筛选快照对跑现行版与改造版。输出每笔到期及预计到账阶梯、存量回落日期、7/30/90 天覆盖、短期容量、未配置余额和参考收益差。另测最大短期候选无额度、主要赎回延迟 3 个工作日两种情景，核对每个刚性付款日是否有缺口。当前比例取自只读核验，压力测试和收益重算属于实施前验收。

## 验收和发布

- 覆盖中期 20% 和长期 10% 恰好达标、超 1 分、额度不得互借、短期容量不足、主动赎回或本金变化造成被动超限、待确认与预留去重、并发采纳、部分成交后取消以及到账延迟。
- 预览、重算、worker 和提案对同一输入给出一致结论。旧提案按新政策复核，历史评价可按冻结版本读取。沿用现有 API 和表结构，副本验证策略契约更新、派生重跑及保留成交事实的版本回退。
- 在临时 SQLite 和受控目录运行定向用例、`npm run check`、`npm test`、`npm run build`、`npm run test:e2e` 及 `node --experimental-test-coverage --test`。批准实施后，按副本对跑结果确定上线与过渡安排。

依据为当前 v9 策略契约、2026-11-09 只读账户复算、11 月 7 日冻结产品池对比。[理财公司理财产品流动性风险管理办法](https://www.nfra.gov.cn/cn/view/pages/rulesDetail.html?docId=1024321)用于核对赎回和延迟风险，20% / 10% 为拟定的账户内部限额。
