# 累计收益精度改造计划

状态：待审批；本计划不执行 schema 迁移、事实修正或生产发布。用户说明：日常截图通常只有两位小数，获取四位小数较麻烦，因此日常流程以两位小数和银行持仓收益为主。

## 问题与目标

ZX040233 的银行明细自 2026-10-26 至 2026-11-09 合计 2.6879 元，按累计值取整为 2.69 元；现有账本先将每笔日收益取整到分，再相加得到 2.71 元。各日按分金额并无错误，不能为了消除差异任意改写其中某日。

目标是让两位小数截图即可完成日常记录；银行页面提供持仓收益时，另存对应产品、截图和截至日期，在持仓页面优先展示这项银行确认值，同时保留账本逐日收益合计及两者差额。它们属于不同口径，不互相覆盖。银行未提供持仓收益时，展示账本累计并标明其口径；已有四位小数明细可选记录，不要求用户日常提供。银行持仓收益受份额、净值精度、交易和赎回等因素影响，不保证所有情形都与逐日收益相加相等；差异仍须对账。

## 首选方案：银行持仓收益快照

- 建立独立的产品持仓收益快照事实：产品代码、确认适用的截至日期、银行显示的持仓收益、可选持仓金额、原始截图证据、录入时间和修正审计；截至日期不明确时不得猜测。快照保存为当时银行展示值，不能填入某日收益或伪装为累计收益调整项。
- 用产品、截至日期、证据内容和事实值设计幂等约束；同日期不同金额作为冲突交由修正流程处理。只有对应持仓范围明确、截图新鲜且未跨越可能改变范围的买入、赎回或切换时，页面才能作为当前银行持仓收益显示；其他情况保留历史快照，并明确标注日期或待核。多批次、部分赎回和重复购买的适用范围不可推断。
- ZX040233 已有的银行截图可作为待核验回填样本：2026-11-09 的持仓金额 5,602.69 元、持仓收益 2.69 元；原始截图和用户确认的日期须共同关联。页面同时显示账本逐日合计 2.71 元，以及 0.02 元口径差。快照不是日收益事实，不参与 `daily_records` 投影。
- 先检查现有截图和持仓估值证据能力，能满足单产品、日期、金额、证据、审计及幂等要求时优先复用；不能满足才设计增量 schema。仅作为展示的银行持仓收益与账本推算净值分开标识，不静默改变总资产、策略评估或已有 API 计算口径。
- 截图只含两位小数时照常按现有流程入账；不要求上传四位小数，不凭账户余额倒推出任意日收益。只有用户方便且银行明确提供时，才使用下面的可选四位精度能力。

## 可选增强：日收益原始精度

- 在 `product_daily_valuations` 增加可空的 `daily_pnl_1e4 INTEGER`，单位为万分之一元；例如 0.5370 元存 5370，-3.2221 元存 -32221。NULL 表示原始四位精度未知，不能视为零。仅接受可精确表达至四位小数的输入，超出精度应明确拒绝而非静默截断；整数运算和范围检查避免浮点误差及溢出。
- 保留 `daily_pnl` 及其现有按分舍入、唯一约束、审计和事务语义。原始值可用时，按统一半远离零规则取整到分必须等于 `daily_pnl`；冲突走显式修正与审计流程。单独改变原始精度即使分值不变，也需保存、留痕并触发相关投影失效。重复请求保持幂等。
- 不从备注自动批量提取或把现有按分数字伪装为四位精度。建立受控回填清单，逐条核对来源、产品、日期、金额、记录 ID 和已有值，只回填经核验的数据；ZX040233 以用户提供的收益明细为依据，包含截图中明确的 0.0000 元。回填前后保存审计，重复执行不重复修改。11 月 2 日及 11 月 9 日覆盖区间仅用于消缺，不分摊收益。
- 日账投影 `daily_records` 继续等于当日产品 `daily_pnl` 按分合计；本次不重写日账或伪造调整项。原始精度与现有两位字段在同一事务内写入，任何校验或投影失败整体回滚。

## 计算口径与兼容

- 可选的高精度产品累计收益：对各条收益优先使用原始整数值，未知精度则使用按分值折算为万分之一元，先求和再按分取整。明确暴露精度状态、原始精度覆盖条数和总条数；存在回退记录时标记“部分精度，估算”，不承诺等于银行值。缺日同样单独标明，不能因精度完整掩盖收益缺口。该能力不是银行持仓收益快照或日常入账的前置条件，可独立分阶段实施。
- 保留现有 API 字段及含义：`cumulative_pnl` 继续是按分日收益之和；新增独立的高精度累计字段及其精度状态，避免静默改变现有消费者、评估冻结证据和总账。产品页面清楚区分两种口径及差额。对外字段、命名与空值语义在实施时固定并添加兼容测试。
- 持仓估值、收益排行、持仓复盘和策略评估分别梳理是否改用新口径，不可直接全局替换。ZX040233 页面可展示经核验的累计值；实际持仓估值与总账存在口径差时须显式显示，不自动造平。多次买入、部分赎回、多个批次和缺失收益的归属未验证前不得声称其累计值等同当前持仓收益。
- 后续人工录入、截图入账、修正及重试都须能接收和保留原始精度，并兼容旧客户端只提供两位数的请求；仅在来源明确具有原始精度时写入原始字段，不能依据数字末尾的零推断精度。变更时重新核对有关审计、数据血缘、幂等、覆盖日和冲突检测。

## 迁移、备份与回滚

1. 获得明确授权后，提供独立、版本化、可重复运行的迁移与回填脚本。生产写入前使用 SQLite 一致性备份方式创建带时间戳的数据库备份，检查完整性并记录路径、schema 版本、目标记录和财务事实指纹；不得简单复制运行中的数据库主文件。
2. 在临时 SQLite 和受控文件目录，先演练备份、增量 DDL、经核对回填、重复执行和失败中断恢复。对目标记录以外的事实、日账和 schema 变更范围做差异核验。
3. 暂停写入并备份后执行生产迁移；先发布兼容新旧 schema 的读取与回退策略，按受控顺序完成迁移与应用部署。逐条核对回填、总账、API、健康状态与日志，再恢复写入。部署、重启按工作区托管契约执行。
4. 回滚优先停写并回退到兼容旧口径的代码，保留新增字段及回填审计以避免丢失迁移后的新数据。若必须恢复整库备份，先保存故障时数据库，并识别、导出和重放备份后产生的合法交易及收益；禁止未经核对直接覆盖这些新事实。恢复后检查完整性、事实计数、关键 API 和服务状态。

## 验收

- 首选方案以两位小数截图为固定回归用例：银行持仓收益显示 2.69 元，账本按分累计显示 2.71 元及差额；所有原日收益和日账保持不变。还须覆盖快照过期、日期不明确、赎回后范围变化、重复截图和同日冲突。
- 如果实施可选精度增强，再使用四位明细验证 11 条合计 2.6879 元、累计取整 2.69 元；四位明细不作为首选方案或日常使用的必要条件。
- 覆盖正负数、零、半分边界、四位精度、超精度拒绝、缺失与混合精度、重复提交、仅原始精度变化、并发与事务失败、跨周覆盖、日期变更及修正审计。
- 检查旧 API 与只传两位数的客户端、产品收益/持仓估值/排行/评估消费者、已赎回与多批次、缺失收益提示及重算行为。界面桌面浅色和深色下显示口径和差额，页面无横向溢出。
- 用临时 SQLite 和受控目录运行定向测试，完成 `npm run check`、`npm test`、`npm run build`、`npm run test:e2e` 和 `node --experimental-test-coverage --test`；生产迁移后核验 `quick_check`、目标记录、日账不变量、健康接口及日志。

## 审批边界

首选方案可能涉及持仓收益快照 schema 和受控历史回填；可选增强还涉及日收益精度 schema。具体迁移须先完成复用能力核查，列出变更、备份、迁移、兼容和回滚方案，并取得明确授权。涉及生产重启时遵循工作区托管规则。本计划本身不构成授权。

## 实施前复用核查与迁移审批

- 旧持仓估值快照保存账户总市值，逐产品子项只保存市值和账本成本，并要求覆盖全部当前持仓。证据可空，日期可默认为今天，现有去重规则也允许同日不同值并存。无法用旧接口录入单产品的银行持仓收益。可复用原图上传、按 SHA-256 去重、原图读取和证据审计能力。
- 首期迁移 `product-holding-income-v1` 新增独立事实表 `product_holding_income_snapshots`，以产品代码和截至日期唯一定位事实。保存有符号收益分、可空持仓金额分、原始证据 ID、经确认的批次 ID（可空，空时只展示历史）、录入与修正时间。金额使用安全整数；日期显式输入并检查真实日历日期。单次交易只覆盖自己的产品，切换同时检查转出、转入。暂以最新已披露收益日为新鲜度判断下限；缺少可判定的披露日、同日交易顺序不明、证据缺失或多批次时按历史展示。旧快照表与原收益表均不改。
- 新增 `product_holding_income_snapshot_revisions`，按事实 ID 与版本号唯一，保留修正前后事实、原图引用、操作者、修正原因和时间。写入在同一事务检查原图、版本和同日冲突，更新事实与审计。相同产品、日期、截图哈希和事实值重放返回已提交结果；同日不同值须显式修正并携带预期版本。修正后重放旧请求仍不得改回旧值。
- 旧库可继续运行，读取新增快照前检查迁移版本；未迁移时显示按分累计，写入入口明确提示未启用。迁移脚本提供 `status`、`apply`、`verify`，登记版本，与增量 DDL 同事务提交。生产停写后复用 SQLite `VACUUM INTO` 一致性备份和 `quick_check`，记录目标与财务事实指纹；在临时库演练重复迁移、失败回滚、旧库读取、快照录入与原表一致性。代码回滚后保留新增表和审计。
- 只读预检结果：库通过 `quick_check`。ZX040233 在目标区间有 11 条日收益，合计 2.71 元，其中 9 条带日收益截图引用。2026-11-09 的旧持仓估值表没有该产品的对应条目。回填只在核验原始银行截图、绑定明确的截至日期及持仓范围后执行，日收益截图引用本身不能证明页面上的持仓收益。
- 四位原始精度保留为第二期。届时单独审批 `product_daily_valuations.daily_pnl_1e4`、目标事实清单与回填，沿用原日收益审计并核对日账指纹。首期验收用临时库复现 2.69 元、2.71 元和 0.02 元口径差。
