# 收益精度与银行累计对账契约

2026-11-20 用户明确要求：先处理当前持仓收益差异，再将日收益改为四位计数。本版替代原待审批的“两位优先、四位可选第二期”方案；实际实施和验收见本次任务记录。历史舍入误差、买入份额/成本舍入和赎回范围可能分别造成差异，四位日收益不保证与银行持仓累计完全相同。

## 日收益与计算

- product_daily_valuations 增量新增 daily_pnl_1e4 INTEGER、daily_pnl_precision INTEGER（2/4）。NULL 表示历史原始精度未知。日常输入允许两位或四位，超过四位拒绝，不强迫截图提供四位。
- daily_pnl 保留按半远离零舍入的分兼容值；daily_pnl_exact 返回原值。不得把旧分值补零声称原始精度已恢复。
- daily_records.daily_pnl_1e4 保存该收益日全部产品有效整数合计；daily_pnl 是当日合计后舍入的分值。历史未知原值按原分值回退，来源覆盖只消缺，不分摊或复制金额。
- 累计、曲线、归因、持仓表现、复盘及未冻结评价使用原始值；原始累计求和后才展示舍入值。cumulative_pnl 现在是该累计的按分展示，legacy_cumulative_pnl 另保留旧按分逐日合计；返回覆盖计数和精度状态。历史冻结决策和已确认评价不改写。
- 同分原始值变化也保存审计并重算；不同四位值冲突不因同为0.98而吞掉，通知以四位整数去重。低精度重放不降精度。

## 当前累计对账与持仓估值

- product_holding_income_snapshots 以产品、显式截至日唯一保存银行收益分、可选持仓金额分、原始证据、截至日完整确认交易范围及指纹。多批次必须明确完整范围，不按名称推断。
- product_holding_income_snapshot_revisions 保存前后版本、原因、操作者及幂等键。同日不同金额需 expected_version 和修正原因；旧请求重放不得恢复旧值。沿用旧银行截图上传和SHA-256证据读取能力，不恢复旧账户总市值手工录入流程。
- 银行累计不写入任何某日日收益，不参与 daily_records、策略资金基数和冻结评价。展示银行截至日、同期账本、差额（银行减账本）和来源精度。
- 持仓范围、证据和本金核验通过且尚无更新日收益时，采用该银行累计；之后仅在范围未变、收益覆盖完整且合并收益未跨基准日时，用基准加后续原始日收益续算，明确标为“银行基准续算”。原银行值及原截止日永不随续算改写。范围变化、缺口或跨基准合并收益停止续算，显示历史或待核并回退账本。
- API 保留原路径、数值类型及分兼容字段，增补精确字段和 GET/POST /api/product-holding-incomes。旧未迁移库可读，四位写入明确拒绝，避免静默丢失。

## 迁移、回填、备份和回滚

1. 生产停写前在一致性副本完整演练；测试只用临时SQLite和受控目录。迁移前采用 VACUUM INTO 创建不可覆盖的一致性备份并验证 quick_check。
2. scripts/migrate-income-precision.mjs 支持 status/apply/verify --db PATH --backup PATH；只做三列增量，不自动回填历史。scripts/migrate-product-holding-income.mjs 显式建立独立累计快照和修正审计表；读取不迁移。
3. 当前银行快照先按各产品截止日录入。日收益回填通过 scripts/restore-income-precision.mjs 的受控清单：冻结目标ID/代码/日期、原分值、原raw/source精度、更新时间、目标四位整数、原图ID及SHA-256。预检和写事务内均核对完整原状态；精确目标已存在才幂等跳过，同分不同raw拒绝。应用前另建一致性备份。
4. 只回填逐图已核验的明细。解析结果可能含跨图手工内容，notes不能独立替代原图。预估明细保留其来源性质，未知精度和未核验原图不得自动恢复。每条修正保留原值和原证据，不任意分摊差额。
5. 生产由原有计划任务托管，暂停、部署和恢复遵循 AGENTS。迁移后核对产品/账户整数不变量、范围、审计、幂等、健康及日志。
6. 首选回滚到兼容精度字段的代码，保留新增列、快照和审计，不丢新事实。整库恢复仅在停写、保存故障库、识别备份后合法写入并计划重放后执行；不得直接用旧备份覆盖新交易。

## 验收要求

正负半分、零、超精度、安全整数、混合/未知精度、仅raw变化、同分冲突、重放、事务失败、旧cash_balance迁移交叉、跨周覆盖、版本修正、范围变化、银行基准续算与收益缺口均须验证。完成 check、test、build、test:e2e 和财务覆盖率测试；界面在桌面浅深主题下验收，信息文字至少12px，无根节点横向溢出。
