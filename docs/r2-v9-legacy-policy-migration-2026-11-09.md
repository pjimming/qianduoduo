# R2 旧策略口径盘点与迁移计划

本计划承接 [v9 流动性改造](r2-v9-liquidity-upgrade-plan-2026-11-09.md)。2026-11-09 以当前工作树、本机生产只读接口和实际启用的 Codex 任务定义核查。

| 优先级 | 入口与现状 | 改造 |
| --- | --- | --- |
| P0 | **选品与配置 → 持仓复核**。`ProductsView.vue` 在 v9 没有任何通过页面证据判定的行时，回退到旧 `HoldingReviewPanel`。生产工作区为 v9 且未过期，11 行全部待核，满足回退条件；旧产品接口同日返回 11 条复核、3 条建议替换。页面徽标也有旧摘要兜底。 | 按策略模式路由。v9 始终呈现 v9 面板，区分待核、待重算、无结果和读取失败；禁止旧建议、旧可分配金额与旧替换按钮混入。legacy 回滚仍可访问原面板。以 11 行全待核作为回归场景。 |
| P1 | **Dashboard 与旧产品 API**。`dashboard/service.js` 仍调用 `buildProductView` 与 `buildHoldingReviews`；`/api/dashboard/products` 仍返回旧 allocation 和 holding_reviews。旧提案服务仍保有路径，存储层在非 legacy 模式已阻止旧策略生成或采纳。 | 盘清 API 调用方，拆开产品证据、持仓财务事实与推荐派生。现行推荐统一读 v9 工作区；兼容期保留旧 API 形状并明确旧结果的策略模式与可执行性，迁完消费者后停止在 v9 常规读路径计算旧建议。保持旧提案采纳的服务端阻断，并测试直接调用旧 API。 |
| P1 | **手工决策、交易和截图补录**。DecisionLogPanel、TradesPanel、TradeInboxPanel 仍带 30/35/35 默认字段或文案。现行决策服务在 v9 契约匹配时会覆盖客户端策略版本和桶计划，契约不匹配时使用原提交数据，缺省版本仍可落到 target3。 | 新建表单从服务端读当前策略摘要，去掉重复写死的桶参数。契约不匹配时给当前策略操作明确阻断；手工决策和已发生交易仍可按事实留存并标为待复核。现行决策冻结上限及策略版本，历史记录按冻结值显示。验收含直接 API、手工录入和截图补录。 |
| P1 | **配置设置和现金流**。v9 的 `service.js` 仍把旧 0–3／3–6／6–12 个月现金需求折成各档末日的累计需求。资金需求发生在档内较早日期时，这个代理日期会掩盖缺口；配置输入仍来自旧设置体系。 | 在 v9 提供当前设置视图，明确策略本金、流动性底线和硬上限。支持按付款日校验。原区间值兼容读取并标记为估算，精确日与区间值同一需求只计一次。先核实现有值和到期用途，再设计持久化；涉及 schema 或既有事实的迁移另行列明备份、兼容和回滚。 |
| P1 | **实际启用的定时任务**。本机 `r2`、`r2-2`、`r2-3`、`r2-4` 定义均已引用 v9 工作区，也都还出现旧 holding_reviews；`r2` 实际提示词仍含 30/35/35。仓库日巡检和周巡检仍有大量旧字段和动作说明。当前核查到的是提示词残留，实际运行是否误用需逐次对照产出。 | `r2-2`、`r2-3` 的当前建议只读 v9 的结果、过期状态、证据及到账字段；`r2` 将 CSV 快照标为研究输入并移除当前配置比例文案；`r2-4` 保留冻结实验规则并标明策略版本。实施时同步仓库文档和实际任务定义，使用模拟或只读巡检验证全待核场景无旧动作。 |
| P2 | **离线脚本、技能和文档**。`yield-verify.cjs` 仍检验旧 holding_reviews，R2 技能的 target3 模型仍为 30/35/35，README、USAGE 和自动化文档也有旧示例。 | 拆开兼容回归、样本外观察与生产 v9 验收。为生产工作区增加独立的口径校验，输出模式、版本和限额；旧校验作为历史兼容。工作区任务以 v9 契约为准，通用模型与项目现行规则分别标注。 |

实施顺序为先关闭页面回退，再以同一策略契约接通 20%／10% 上限、提案校验和手工决策展示，随后迁移现金流输入、API 消费者和自动化提示词。旧深链保留并进入对应的当前页面。冻结评价、旧决策快照、独立样本外观察及 legacy 回滚路径保留原版本，收益事实和到账事实沿用账本口径。

联验覆盖 v9 正常、全待核、过期、接口失败、契约不匹配、旧提案直接采纳和 legacy 回滚。以生产一致性副本核对旧建议不进入 v9 当前页面或巡检、已成交交易可补录、策略回滚后事实与历史评价可读。实际任务定义变更与代码发布在实施阶段完成。

## 实施记录

- 当前建议由 v9 工作区提供。Dashboard 保留旧配置与复核字段供兼容和离线研究，并通过 `strategy_recommendation` 标识其来源。v9 下已移除 Dashboard 持仓摘要中的旧复核提醒。
- 新配置契约使用 `r2-v9-bucket-allocation-v2`。旧 v9 合约哈希只允许用于冻结评价；旧待采纳提案通过契约升级作废，旧已采纳提案的未执行部分标为待复核，已成交凭证仍可归档。
- 精确现金需求使用现有配置存储，不新增表。指定付款日后按日期累计，空列表明确表示无待付款需求。旧分档保留作兼容估算。
- 本机 `r2`、`r2-2`、`r2-3`、`r2-4` 已同步当前策略读取规则，运行周期沿用原设置。
- 生产一致性副本演练 v9/1 → v9/2 → legacy/3 → v9/4，通过 SQLite 完整性检查。新限额下中期超 ¥4,100、长期超 ¥10,100，暂无可执行买入方案。副本中各持仓的到账日期仍待核，7／30／90 天均无可核实的计划到账额。额度丢失和到账延迟用受控样例验证，生产参考收益差没有可执行组合可供比较。
- 生产已激活 v9/2，工作区最新派生完成，健康和关键 API 正常。切换前备份为 `data/backups/r2_ledger-v9-liquidity-precutover-2026-11-09.sqlite`，通过 SQLite 检查。生产表结构、交易、决策、产品收益、逐日账本与历史评价均与备份逐行一致。
