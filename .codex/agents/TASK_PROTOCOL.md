# 子 Agent 任务上下文协议

本协议用于避免子 Agent 启动后丢失任务、沿用旧任务，或只回复“请提供任务”。主 Agent 和所有项目级子 Agent 都必须遵守。

## 主 Agent 派发

1. 为每次派发生成唯一 `TASK_ID`，格式建议为 `<DOMAIN>-<TOPIC>-<YYYYMMDD>-<序号>`。
2. 在 `run/agent-briefs/<TASK_ID>.md` 创建任务简报。`run/` 已被忽略，不得提交任务简报。
3. 直接调用一次 `spawn_agent`。需要当前会话、用户要求或既有研究上下文时，显式传入 `fork_turns="all"`；本工作区禁止使用 `fork_turns="none"`。
4. 不得通过批量工具包装器创建需要上下文的任务。多个子 Agent 应逐个直接创建，再等待其并行完成。
5. 提示词只写一行入口：读取 `AGENTS.md`、本协议和指定简报，完成该 `TASK_ID`，不要依赖入口提示复述全部需求。
6. 只接受首行带正确 `CONTEXT_OK <TASK_ID>` 且目标一致的答复。缺失、错 ID、执行了其他任务或要求重新提供已知目标时，立即停止该 Agent，修正简报后以新的 `TASK_ID` 重新派发。
7. `followup_task` 只用于已正确接单 Agent 的后续工作，不用于修复上下文失败。
8. 汇总结果后删除对应的 `run/agent-briefs/<TASK_ID>.md`。

## 任务简报模板

```markdown
# <TASK_ID>

- 目标：
- 用户原始要求：
- 研究/执行截止：
- 当前工作目录：
- 必须读取：
- 可读范围：
- 可写范围：
- 禁止事项：
- 交付格式：
- 验证命令或证据：
- 完成条件：
- 阻塞时返回：
```

简报必须足以独立判断任务边界；不要把关键信息只放在创建 Agent 的临时消息里。

## 子 Agent 接单

1. 先读取 `AGENTS.md`、本协议和主 Agent 指定的任务简报。
2. 开工前发送一条简短进展，首句为 `CONTEXT_OK <TASK_ID>：<一句话目标>`。
3. 最终答复首行再次写 `CONTEXT_OK <TASK_ID>`，然后给出证据、文件、命令、结果或阻塞。
4. 简报不存在、`TASK_ID` 不一致、目标冲突或无法读取必需上下文时，只返回 `CONTEXT_MISSING <TASK_ID>：<具体缺失项>`，不得猜测或改做其他任务。

## 写入与冲突

- 只写简报授权的路径；多个 Agent 不得同时写同一文件、生成物、数据库或共享状态。
- 股票报告只可写各自唯一 `report/*.html`；应用内副本、清单、导航、构建和发布由主 Agent 统一处理。
- 后端事务、数据库 schema、生产重启等高风险操作必须使用独占任务，并按串行顺序执行。
